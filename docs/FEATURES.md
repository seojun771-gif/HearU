# 기준 모델 특징 기록 (MFCC + 주파수 변화 + 소리 크기 변화)

- 코드: `ai/features.py` (특징 추출), `ai/train_features.py` (학습·평가)
- 결과: `ai/results/<이름>.md`·`.json` / 모델: `ai/models/<이름>.joblib`
- 실행: `python train_features.py` (기준 모델) / `python train_features.py --data <폴더> --name <이름>` (두 번째 모델)

## 1. 전처리 (세 특징 공통)

| 단계 | 내용 |
|---|---|
| 입력 | 원본 WAV → 16kHz mono float (`librosa.load`) |
| 구간 | 1.5초(24,000샘플). 길면 0.1초 간격으로 훑어 에너지가 가장 큰 1.5초를 자르고, 짧으면 뒤에 0을 채움 |
| 정규화 | 최대 절댓값이 1이 되도록 나눔 (마이크 거리·볼륨 차이 완화) |
| 분석 창 | STFT n_fft 512 (32ms), hop 256 (16ms), Hann 창 → 약 94프레임 |
| 증강 (학습용만) | 볼륨 ×0.5~1.5, 시간 이동 ±0.2초, 배경 잡음 최대 2%. 파일당 3개 |

## 2. 특징별 계산 방법 (총 136차원)

### MFCC (120차원)

| 항목 | 값 |
|---|---|
| 계수 | 40개 (c0~c39). c0는 전체 에너지(소리 크기)에 해당, c1~c39는 스펙트럼 모양 |
| 멜 필터 | 128개, 0~8,000Hz |
| 계산 | 파워 스펙트럼 → 멜 필터 → log(dB) → DCT-II (librosa 기본) |
| 요약 | 계수별 **평균 40** + **표준편차 40** + **1차 변화량(delta, 9프레임) 평균 40** |

### 주파수 변화 (10차원)

| 특징 | 계산 |
|---|---|
| centroid_mean / std | 프레임별 스펙트럼 중심 주파수의 평균 / 표준편차 |
| centroid_change | 중심 주파수의 프레임 간 변화량 절댓값 평균 |
| rolloff_mean / std | 에너지 85%가 모이는 주파수의 평균 / 표준편차 |
| dominant_mean / std | 80Hz 이상에서 가장 강한 주파수의 평균 / 표준편차 |
| dominant_change | 대표 주파수의 프레임 간 변화량 절댓값 평균 |
| flux_mean / std | 음량을 정규화한 스펙트럼의 프레임 간 변화량(유클리드 거리) 평균 / 표준편차 |

### 소리 크기 변화 (6차원)

| 특징 | 계산 |
|---|---|
| db_mean / db_std | 프레임 에너지 dB의 평균 / 표준편차 |
| db_range | 최대 dB − 최소 dB |
| db_change | 프레임 간 dB 변화량 절댓값 평균 |
| db_max_rise | 한 프레임 사이 가장 크게 커진 dB |
| db_rise_count | 한 프레임 사이 6dB 넘게 커진 횟수 (두드림처럼 순간적인 소리) |

## 3. 모델·평가

| 항목 | 값 |
|---|---|
| 모델 | StandardScaler → MLP (은닉층 128, 64 / alpha 1e-3 / early stopping / seed 42) |
| 평가 | 파일 단위 5겹 층화 교차검증. 증강은 학습 폴드에만 적용 (같은 녹음이 시험에 섞이지 않게) |
| 최종 모델 | 전체 데이터 + 증강으로 다시 학습해 저장 |

### 모델 1 추가 학습: 화재·초인종 ESP32 녹음 60개 추가 (`esp32`, 2026-11-22)

추가 데이터 `second/` ZIP 2개 (ESP32, 폰 최대 볼륨 재생): 화재 30 · 초인종 30, 조건별 10개씩 (조용함 30cm / 조용함 2m / TV 소리 1m)
→ 전체 244개: 기타 80 · 화재 40 · 아기 울음 20 · 초인종 61 · 노크 43

평가 방법 추가: **B. 녹음 묶음 단위 교차검증.** 같은 날·같은 조건으로 녹음한 묶음(ESC-50은 같은 원본 클립)이 학습과 시험에 함께 들어가지 않게 나눈다. 같은 녹음의 비슷한 파일이 양쪽에 섞이는 A보다 실제 성능에 가깝다.

| 평가 | 정확도 | Macro F1 | 기타 | 화재 | 아기 울음 | 초인종 | 노크 |
|---|---|---|---|---|---|---|---|
| 이전 기준 모델 (A) | 0.77 | 0.70 | 0.79 | 0.30 | 0.65 | 0.77 | 0.91 |
| **추가 학습 (A. 파일 단위)** | 0.84 | 0.81 | 0.81 | 0.72 | 0.65 | 0.95 | 0.93 |
| **추가 학습 (B. 녹음 묶음 단위)** | 0.80 | 0.79 | 0.86 | 0.70 | 0.70 | 0.89 | 0.70 |

- 화재 재현율 0.30 → 0.70. 새 녹음 30개만 보면 0.80(B), 11/17 녹음 10개는 0.40으로 여전히 낮다(초인종과 같은 주파수대).
- 조건별 화재 재현율(B): 30cm 0.80 · 2m 0.70 · TV 소리 0.90.
- 화재·초인종 원본 소리가 한 종류씩뿐이라, B도 '처음 듣는 다른 화재경보기'에서의 성능보다 높게 나온다.
- 상세: `ai/results/esp32.md`

### 모델 2: 노트북 마이크 (녹음 대기)

ESP32 비교 녹음과 같은 소리·볼륨·조건으로 노트북 마이크에 녹음해 학습하고 마이크별로 비교한다. 비교표: [MODEL_COMPARISON.md](MODEL_COMPARISON.md)

```
cd ai
python record_laptop.py fire        # 조건 3개 x 10회 (Enter로 한 번씩)
python record_laptop.py doorbell
python train_features.py --data data data_laptop --exclude esp32 --name laptop --test-on data --test-match esp32_20261122
python train_features.py --exclude esp32_20261117 --name esp32_1122 --test-on data_laptop
python compare_models.py
```

- 공정 비교를 위해 모델 1 쪽도 11/22 ESP32 녹음만 넣은 `esp32_1122`를 쓴다. 두 모델은 공통 데이터(ESC-50 + 이전 직접 녹음)가 같고, 화재·초인종 60개의 마이크만 다르다.
- `--test-on`: 한 마이크로 학습한 모델을 다른 마이크의 녹음으로 시험한다(C).
