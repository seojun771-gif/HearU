# 코드 읽기 가이드 (ai/)

`ai/` 폴더의 코드가 각각 무슨 역할인지 설명하는 팀원용 안내서입니다. 위에서 아래로 읽으면서 해당 파일을 같이 열어 보세요.
- 코드가 뭔지 1분 만에 보고 싶다면 → [OVERVIEW](OVERVIEW.md)
- 실행 방법과 전체 구조 → [README](../README.md)
- 녹음 데이터를 모으는 방법 → [DATA_COLLECTION](DATA_COLLECTION.md)

## 1. 한눈에 보기

HearU의 AI는 **소리를 두 갈래로 동시에 판단**하도록 설계돼 있습니다.

```
                          ┌─ ① AI 모델 경로 (6종 분류) ──────────────────────────┐
소리(wav / 마이크) ────────┤  common.extract → model.joblib → infer.classify     │→ infer.to_uart → FPGA
                          │  (MFCC 120개 숫자)  (MLP)        (신뢰도 판정)        │   "RESULT,1,FIRE,89,1"
                          └──────────────────────────────────────────────────────┘
                          ┌─ ② 화재 규칙 경로 (모델과 독립, 안전망) ───────────────┐
                          └─ fire_rule.analyze (3kHz 대역 + 반복 리듬)  ──────────┘→ (아직 FPGA/UART와 연결 안 됨)
```

- **① 모델 경로**는 6종(화재·아기 울음·초인종·문 두드림·사람 호출·기타)을 분류합니다. **학습 데이터가 필요합니다.**
- **② 규칙 경로**는 화재경보음만 봅니다. 모델 없이 "3kHz대 고음이 정해진 리듬으로 반복되는가"만 확인하므로 **학습이 필요 없고**, 모델이 화재를 놓쳐도 잡아내는 안전망 역할입니다.

### 파일별 역할 요약

| 읽는 순서 | 파일 | 역할 | 누가 보면 좋은가 |
|---|---|---|---|
| 1 | `shared/labels.json` | 클래스 번호·이름·우선순위·임계값의 **단일 기준** | 모두 |
| 2 | `ai/common.py` | 소리 → 숫자 변환 (학습·추론 공용) | AI |
| 3 | `ai/train.py` | 녹음 파일로 모델 학습·평가·저장 | AI |
| 4 | `ai/infer.py` | 학습된 모델로 분류, 신뢰도 판정, **UART 메시지 생성** | **FPGA**, AI |
| 5 | `ai/fire_rule.py` | 화재경보 **규칙 검출기** (3kHz 대역 + 반복 리듬) | **FPGA**, AI |
| 6 | `ai/test_fire_rule.py` | `fire_rule.py` 자동 테스트 (합성 소리) | AI |
| 7 | `ai/check_data.py` | 수집한 녹음의 개수·품질 점검 | 데이터 수집 담당 |
| 8 | `ai/fetch_public_data.py` | 공개 데이터셋(ESC-50)에서 knock·baby_cry·unknown 녹음을 받아 변환 | 데이터 수집 담당 |

### 어떤 순서로 쓰나 (작업 흐름)

```
녹음 / fetch_public_data.py (공개 데이터) → check_data.py (개수·품질 점검) → train.py (학습) → infer.py (분류 / 실시간)
                                                     └→ fire_rule.py (화재 규칙, 독립 실행)
```

### `ai/` 폴더 구성

```
ai/
├─ common.py            공통: 설정, 오디오 읽기, 특징 추출
├─ train.py             학습
├─ infer.py             추론 + UART 메시지
├─ fire_rule.py         화재 규칙 검출기
├─ test_fire_rule.py    화재 규칙 테스트
├─ check_data.py        데이터 점검
├─ fetch_public_data.py 공개 데이터셋(ESC-50) 다운로드·변환
├─ requirements.txt     설치할 패키지 목록
├─ data/                녹음 파일 (git에 안 올라감)  data/<label>/*.wav
├─ model.joblib         학습 결과 (git에 안 올라감, train.py가 생성)
└─ .venv/               파이썬 가상환경 (git에 안 올라감)
```

## 2. `shared/labels.json` — 약속 파일

```json
{"id": 1, "name": "FIRE", "ko": "화재경보기", "priority": 1}
```

- `id`: UART로 나가는 class_id. **FPGA의 클래스 번호와 반드시 같아야 합니다.**
- `priority`: 숫자가 작을수록 우선 (FIRE=1 … UNKNOWN=6).
- `thresholds`: `confirm 0.80`(확정), `weak 0.60`(약한 알림). 이 아래는 UNKNOWN.
- `cooldown_sec`: 같은 클래스 재알림 최소 간격(5초).

| id | name | 의미 | priority |
|---|---|---|---|
| 0 | UNKNOWN | 기타 | 6 |
| 1 | FIRE | 화재경보기 | 1 |
| 2 | BABY_CRY | 아기 울음 | 2 |
| 3 | DOORBELL | 초인종 | 3 |
| 4 | KNOCK | 문 두드림 | 4 |
| 5 | CALL | 사람 호출 | 5 |

번호나 임계값을 바꾸려면 코드가 아니라 **이 파일만** 수정하세요. 코드는 여기서 읽어 갑니다.
(데이터 폴더 이름은 `name`을 소문자로 바꾼 것입니다: `fire/`, `baby_cry/`, `doorbell/`, …)

## 3. `ai/common.py` — 소리를 숫자로 바꾸기

모델은 파형을 그대로 읽지 못해서 "소리의 특징"을 숫자 벡터로 바꿔 넣습니다. 학습할 때와 추론할 때 **같은 함수**를 써야 결과가 어긋나지 않아서 한 파일에 모아 뒀습니다. `train.py`, `infer.py`, `check_data.py`, `fire_rule.py`가 모두 이 파일을 가져다 씁니다.

| 상수 | 값 | 의미 |
|---|---|---|
| `SR` | 16000 | 샘플링 레이트 (Hz) |
| `DURATION` / `N_SAMPLES` | 1.5초 / 24000 | 모델 입력 길이 |
| `N_MFCC` | 40 | MFCC 계수 개수 |
| `DATA_DIR`, `MODEL_PATH` | `ai/data`, `ai/model.joblib` | 데이터·모델 위치 |

- **`load_wav(path)`**: 파일을 16kHz mono로 읽습니다. 다른 샘플레이트도 자동 변환됩니다.
- **`fix_length(y)`**: 길이를 24000샘플(1.5초)로 맞춥니다. 길면 에너지가 가장 큰 1.5초 구간을 자르고, 짧으면 뒤를 0으로 채웁니다.
- **`extract(y)`**: 특징 벡터(120차원)를 만듭니다. ① 길이 맞춤 → ② 최대 진폭으로 나눠 정규화(마이크 거리·볼륨 차이 완화) → ③ MFCC 40개의 시간 평균(40) + 표준편차(40) → ④ MFCC 변화량(delta) 평균(40).

> **전자과 관점 설명**: MFCC는 FFT로 주파수 성분을 구한 뒤, 사람 귀처럼 저주파를 촘촘하게(멜 스케일) 묶고 로그·DCT로 압축한 값입니다. "이 소리의 주파수 모양"을 40개 숫자로 요약한 것이라고 보면 됩니다.

## 4. `ai/train.py` — 학습

```
data/<label>/*.wav → 파일 단위 train/test 분리 → train에만 증강 → 특징 추출
                  → StandardScaler + MLP 학습 → 평가 출력 → model.joblib 저장
```

실행: `python train.py`

- **`load_files()`**: `ai/data/<label>/` 폴더를 읽어 (파일 경로, 클래스 id) 목록을 만듭니다. 클래스별 파일 수를 출력하고, 데이터가 하나도 없으면 안내 후 종료합니다.
- **`augment(y)`**: 데이터 부족 보완용 증강. 볼륨 0.5~1.5배, ±0.2초 시간 이동, 약한 백색 잡음.
- **`build(paths, labels, n_aug)`**: 파일마다 특징을 추출합니다. `n_aug=3`이면 원본 1개 + 증강 3개 = 4개로 늘립니다(학습용만).
- **`main()`**: 전체 흐름. 마지막에 클래스별 precision/recall/F1과 혼동행렬을 출력하고 `model.joblib`을 저장합니다.

**설계 포인트**
1. **파일 단위로 먼저 나눈 뒤 증강**합니다. 같은 녹음의 변형이 학습과 테스트에 동시에 들어가면 성능이 부풀려지기 때문입니다.
2. 모델은 `StandardScaler → MLPClassifier(128, 64)`를 `make_pipeline`으로 묶었습니다. 정규화까지 함께 저장·로드됩니다.
3. 출력에서 **FIRE, BABY_CRY의 recall**을 먼저 보세요(목표 95% 이상). 위험 소리를 놓치지 않는 것이 핵심 지표입니다.
4. 혼동행렬은 행=정답, 열=예측입니다. 대각선 밖에 큰 값이 있으면 서로 헷갈리는 클래스입니다.

**주의**
- **클래스가 하나뿐이어도 에러 없이 끝나고 정확도 1.00이 나옵니다.** 이 숫자는 의미가 없습니다. 파일이 있는 클래스가 최소 2개 이상인지, 학습 시작 때 출력되는 클래스별 파일 수를 꼭 확인하세요.
- 테스트는 전체 파일의 20%뿐이라, 클래스당 파일이 적으면(10개면 테스트 2개) recall 숫자가 크게 흔들립니다.

## 5. `ai/infer.py` — 추론과 FPGA 출력 (FPGA 팀원 필독)

실행: `python infer.py sample.wav` (파일) / `python infer.py --mic` (마이크 실시간)

- **`classify(y)`**: 파형 → 결과 딕셔너리.
  1. `extract`로 특징 추출 → 모델의 `predict_proba`로 클래스별 확률
  2. 가장 높은 확률 = `confidence`, 그 클래스 = 후보
  3. 판정:

     | confidence | level | 동작 |
     |---|---|---|
     | ≥ 0.80 | `CONFIRMED` | 해당 클래스 확정 |
     | 0.60 ~ 0.80 | `WEAK` | 클래스는 유지, 약한 알림 |
     | < 0.60 | `UNKNOWN` | 클래스를 UNKNOWN(0)으로 덮어씀 |

  ```python
  {'class_id': 1, 'label': 'FIRE', 'ko': '화재경보기',
   'confidence': 0.89, 'level': 'CONFIRMED', 'priority': 1}
  ```

- **`to_uart(r)`**: 결과를 FPGA용 한 줄 텍스트로 만듭니다. confidence는 0~100 정수로 반올림합니다.
  ```
  RESULT,class_id,label,confidence(0~100),priority\n
  RESULT,1,FIRE,89,1
  ```

- **`run_mic()`**: PC 마이크 실시간 모드.
  - 1.5초 버퍼를 0.5초마다 한 칸씩 밀면서 매번 추론합니다(슬라이딩 윈도).
  - 평균 음량(RMS)이 0.01(-40 dBFS) 미만이면 무음으로 보고 건너뜁니다. **너무 작게 녹음된 소리는 여기서 무시됩니다.**
  - UNKNOWN이거나, 같은 클래스가 5초 안에 또 감지되면 출력하지 않습니다(쿨다운).
  - 추론 시간(ms)도 같이 출력합니다. 목표는 500ms 이하입니다.

**아직 없는 것**: `run_mic()`는 **PC 마이크용**입니다. FPGA에서 UART로 PCM/특징값을 받는 입력부와, 결과를 UART 포트로 실제로 내보내는 코드(`serial_bridge.py`)는 없습니다. 지금은 메시지 문자열을 만들어 화면에 출력하는 단계입니다.

## 6. `ai/fire_rule.py` — 화재경보 규칙 검출기 (모델과 독립)

AI 모델의 확률만 믿지 않고, **화재경보음의 물리적 특징**으로 한 번 더 판단하는 안전망입니다. 학습 데이터가 필요 없습니다.

**원리** (전자과 관점): 연기감지기 경보음은 약 3kHz의 순음에 가깝고 정해진 리듬으로 울립니다.
- **T-3 (화재)**: 0.5초 울림 / 0.5초 쉼 × 3회 → 1.5초 쉼 → 반복
- **T-4 (일산화탄소)**: 0.1초 울림 / 0.1초 쉼 × 4회 → 5초 쉼 → 반복

**처리 단계**
```
파형 → band_frames : 10ms마다 "2.7~3.8kHz 대역이 에너지의 30% 이상이고 소리가 충분히 큰가?" (FFT 512점)
     → pulses      : 연속된 "예" 프레임을 하나의 울림으로 묶음 (30ms 이하 끊김은 합침, 40ms 미만은 버림)
     → _longest_run: 울림 길이와 쉬는 간격이 T-3/T-4 규칙에 맞는 울림이 연속 몇 번인가
     → analyze     : 최종 판정
```

**판정 단계**

| 판정 | 조건 | 합성 소리 기준 알림 시점 |
|---|---|---|
| `CONFIRMED` | T-3 울림 3회 또는 T-4 울림 4회가 규칙적으로 이어짐 | 경보 시작 후 약 2.4초 |
| `CANDIDATE` | 규칙적인 울림 2회, 또는 대역 고음이 1초 이상 지속 | 경보 시작 후 약 1.4초 |
| (없음) | 위에 해당 없음 | — |

`CANDIDATE`는 빠른 예비 알림용입니다. 주전자 휘파람처럼 계속 울리는 고음도 `CANDIDATE(CONTINUOUS)`까지만 올라가고 확정되지 않습니다.

**주요 함수·클래스**
- **`analyze(y)`**: 파형 전체를 보고 `{"level", "pattern", "pulses"}`를 반환합니다. 파일 검사용.
- **`FireRuleDetector.feed(chunk)`**: 실시간용. 짧은 조각을 계속 넣으면 최근 6초를 보고 판정합니다.
- **`run_mic()`**: 0.1초 간격으로 마이크를 읽습니다. 같은 단계는 5초 쿨다운 동안 다시 알리지 않고, `CANDIDATE → CONFIRMED` 승격은 바로 알립니다.

**조정 가능한 값** (파일 위쪽 상수): `BAND`(2700~3800Hz), `BAND_RATIO`(0.30), `RMS_GATE`(0.003, 약 -50 dBFS), `PATTERNS`(T3/T4의 울림·쉼 길이 범위와 필요 횟수), `CONTINUOUS_SEC`(1.0초).

**한계 (중요)**
- 임계값은 **합성 소리로만** 맞췄습니다. 실제 경보기 녹음으로 다시 검증·조정해야 합니다.
- 520Hz 저주파 경보기, 음성 안내형 경보기는 다루지 않습니다.
- 아직 `infer.py`와 합쳐져 있지 않고, UART 메시지에도 실리지 않습니다(아래 확인 사항 참고).

실행: `python fire_rule.py alarm.wav` (파일) / `python fire_rule.py --mic` (마이크)

## 7. `ai/test_fire_rule.py` — 화재 규칙 테스트

`fire_rule.py`가 의도대로 동작하는지 **합성 소리**로 자동 확인합니다. 임계값을 고친 뒤에는 꼭 다시 돌리세요.

실행: `python -m unittest test_fire_rule -v` (현재 15개 모두 통과)

| 묶음 | 확인하는 것 |
|---|---|
| `DetectsAlarm` | T-3·T-4 경보음, 다른 음높이(2.9/3.3/3.5kHz), 작은 소리, 백색잡음·TV 대화 섞인 경우를 `CONFIRMED`로 잡는가. 울림 2회는 `CANDIDATE`인가 |
| `IgnoresOtherSounds` | 무음, 백색잡음, 대화, 초인종(딩동), 같은 리듬의 낮은 소리(1kHz), 울림 1회는 무시하는가. 계속 울리는 고음은 `CANDIDATE`까지만 가는가 |
| `Streaming` | 0.1초씩 넣을 때 `CANDIDATE`는 1.5초 이내, `CONFIRMED`는 2.5초 이내에 나오는가 |

> 모두 합성 소리입니다. **테스트 통과 ≠ 실제 경보기에서 잘 동작**을 뜻하지 않습니다.

## 8. `ai/check_data.py` — 녹음 점검

학습 전에 수집한 녹음이 쓸 만한지 확인하는 점검 도구입니다. 파일을 수정하거나 학습하지는 않습니다.

실행: `python check_data.py` (1단계 목표 기준) / `python check_data.py --stage 2` / `--stage 3`

**하는 일**
- 클래스별 파일 개수를 단계별 목표와 비교해 "남은 개수"를 보여 줍니다.

  | 단계 | doorbell | fire | unknown | knock · baby_cry |
  |---|---|---|---|---|
  | 1 | 30 | 30 | 60 | — |
  | 2 | 50 | 50 | 100 | 각 30 |
  | 3 | 100 | 100 | 300 | 각 100 |

- `.wav` 파일마다 문제를 찾습니다(`inspect`):

  | 점검 | 기준 |
  |---|---|
  | 형식 | 16kHz / mono / 16bit가 아니면 경고 |
  | 너무 짧음 | 1초 미만 |
  | 클리핑 | 최대 진폭 ≥ 0.999 (소리가 찢어짐) |
  | 소리가 작음 | 최대 진폭 < 0.1 (-20 dBFS 미만) |
  | 앞부분 여유 없음 / 끝까지 소리가 남 | 첫(끝) 50ms 구간이 최대 음량의 절반 이상 → 소리가 잘렸을 수 있음 |
  | 중복 | 내용이 같은 파일 (md5) |

- 학습을 시작하기 위한 안내: 파일이 있는 클래스마다 최소 2개가 필요합니다(학습/테스트 분할).

> 경고 기준(-20 dBFS)은 최소선이고, 녹음할 때 권장 음량은 -10 dBFS 이상입니다([DATA_COLLECTION](DATA_COLLECTION.md) 참고).

## 9. `ai/fetch_public_data.py` — 공개 데이터 받기

직접 녹음하는 시간을 줄이기 위해, 공개 환경음 데이터셋 **ESC-50**(2000개 클립)에서 필요한 소리를 받아 16kHz mono 16bit wav로 바꿔 `ai/data/<label>/`에 넣습니다.

| 라벨 | 가져오는 ESC-50 카테고리 | 기본 개수 |
|---|---|---|
| `knock` | door_wood_knock | 40 |
| `baby_cry` | crying_baby | 40 |
| `unknown` | 생활소리 20종 (키보드, 마우스, 기침, 웃음, 발소리, 박수, 청소기, 세탁기, 물소리, 개·고양이, **알람시계, 사이렌** 등) | 종류당 8 = 160 |

**못 받는 것: `fire`(연기감지기 경보음), `doorbell`, 사람 말소리(대화).** 이 셋은 직접 녹음하거나 다른 출처(예: FSD50K의 Smoke detector)에서 구해야 합니다.

**동작**
- 알람시계·사이렌은 화재경보와 헷갈리기 쉬운 소리라 `unknown`에 일부러 넣었습니다. 모델이 "경보 비슷한 소리 = 화재"로 배우지 않게 하기 위해서입니다. 반대로 알람시계를 `fire`에 넣으면 안 됩니다.
- 같은 원본 녹음(`src_file`)이 겹치지 않게 서로 다른 원본을 먼저 고릅니다.
- 이미 받은 파일은 건너뜁니다. 파일 이름은 `esc50_...`로 시작하므로, 지우려면 `esc50_*.wav`만 삭제하면 됩니다.
- 출처는 `ai/data/public_sources.csv`에 기록됩니다 (원본 파일명, 카테고리, Freesound 원본 ID, fold).

**실행**: `python fetch_public_data.py --dry-run` (받을 목록만 확인) → `python fetch_public_data.py` → `python check_data.py`
옵션: `--knock N`, `--baby-cry N`, `--unknown-per-class N`

**주의**
- **라이선스는 CC BY-NC 3.0(비영리)이고 클립별 원 라이선스도 제각각입니다.** 개발·중간보고용으로만 쓰고, 제품 학습 데이터로는 직접 녹음이나 라이선스가 확인된 데이터로 바꿔야 합니다.
- `check_data.py`가 이 파일들에 "클리핑", "앞부분 여유 없음", "끝까지 소리가 남"을 많이 표시합니다. ESC-50 클립은 긴 녹음에서 5초씩 잘라 최대 음량으로 맞춘 것이라 생기는 현상으로 보이고, 직접 녹음의 문제와는 성격이 다릅니다.
- 같은 원본에서 나온 여러 구간이 학습과 테스트에 섞일 수 있습니다(`train.py`는 파일 단위로 분할). 성능이 높게 나올 수 있으니, 나중에 `src_file` 기준으로 나누는 것이 좋습니다.
- 공개 데이터는 실제 장치 마이크를 거친 소리가 아닙니다. 최종 평가는 직접 녹음으로 해야 합니다.

| 항목 | 상태 |
|---|---|
| 학습·추론·UART 메시지 생성 | 동작함 (합성 데이터로 흐름 확인) |

| 공개 데이터 스크립트 | 동작 확인함 (임시 폴더에서 소량 테스트). 실제 `ai/data/`에는 아직 받지 않음 |

수집한 doorbell 11개는 모두 소리가 작게 녹음돼 있어(-23 ~ -34 dBFS) 보충 녹음이 필요합니다. 다음 단계는 fire·unknown 녹음 수집입니다.

## 13. 알려진 한계

- 실제 데이터로 학습·평가한 적이 없어 모델 성능 수치가 없습니다.
- 화재 규칙 검출기는 합성 소리로만 검증했고, 모델(`infer.py`)과 연결돼 있지 않습니다.
- `train.py`의 데이터 분할은 8:2 단순 분할입니다(개발 가이드는 70/15/15). 클래스 가중치, Mel-spectrogram + CNN 비교도 없습니다.
- 같은 날·같은 장소에서 녹음한 파일끼리는 소리가 비슷해서, 지금 방식(파일 단위 무작위 분할)은 성능이 높게 나올 수 있습니다.
- 환경별(조용/잡음/문 닫힘) 평가, 추론시간 통계, 임계값별 Precision-Recall은 `evaluate.py`로 추가할 예정입니다.
